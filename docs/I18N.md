# Languages and formats

The calendar is available in **English** (`en-US`) and **Portuguese** (`pt-PT`). It uses [vue-i18n](https://vue-i18n.intlify.dev/) for its text, and Vuetify's locale for the date pickers.

## Set it up

Register the calendar's messages in your app's vue-i18n instance, under the locale codes `en` and `pt`:

```js
import { createI18n } from 'vue-i18n';
import { translations } from 'vue-calendarium';

export const i18n = createI18n({
  legacy: false,          // the calendar needs the Composition API mode
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en: translations.en,
    pt: translations.pt
  }
});
```

Then choose the language when you create the calendar:

```js
const calendarApp = createCalendar({
  views: [createViewMonth()],
  locale: 'pt-PT'            // 'en-US' (default) or 'pt-PT'
});
```

## Changing the language

```js
calendarApp.setLocale('pt-PT');
```

The calendar updates everything at once: its own labels and dialogs, month and weekday names, the event times, and the date pickers.

## How it shares your app's language

The calendar uses your app's vue-i18n instance, not a private one. This has two effects you should know about:

- **The calendar sets your app's language.** When the calendar's `locale` is set, or changes, it sets vue-i18n's locale to `en` or `pt` to match. Vuetify's language is set inside the calendar only (its date pickers), with Vuetify's own `en` and `pt` translations, so your app's Vuetify components keep their language and you do not need to register Vuetify's Portuguese messages. Create the calendar with the language your app is using. If your app has its own language switcher, call `calendarApp.setLocale()` from it, so the two stay together.
- **The other way does not happen.** Changing your app's vue-i18n locale does not change the calendar. Only `calendarApp.locale` does.

Other locale values, such as `fr-FR`, are not supported. The calendar's text then falls back to English, but dates are still formatted with the value you passed, so you would get a mix of the two languages.

## Changing the wording

Merge your own text over the built-in messages. The message keys are the same in both languages, and you can list them with `Object.keys(translations.en)`.

```js
messages: {
  en: {
    ...translations.en,
    eventTitle: 'Meeting name',
    save: 'Book it',
    // your app's own messages
    appName: 'Planner'
  },
  pt: {
    ...translations.pt,
    eventTitle: 'Nome da reunião',
    save: 'Reservar'
  }
}
```

## Dates and times

| | Format |
| --- | --- |
| Time | Always 24-hour: `09:30`, `14:00`. There is no AM/PM option. |
| Hour labels in the grid | `07:00`, `08:00` |
| Month title | The month and year in the selected language, for example "January 2026" or "Janeiro 2026" |
| Weekday names | In the selected language |
| First day of the week | Always Monday |
| Date field in the create dialog | `dd/mm/yyyy` in both languages |
| Details dialog | Weekday, date and time range: "Wednesday, January 15 · 10:00 – 11:00" or "quarta-feira, 15 de janeiro · 10:00 – 11:00" |
| Durations in the end time list | "(30 min)", "(1 hr)", "(1.5 hrs)" or "(30 minutos)", "(1 hora)", "(1,5 horas)" |
| Repeat menu | "Weekly on Wednesday", "Monthly on the third Wednesday", "Annually on January 15" or "Semanalmente (quarta-feira)", "Mensalmente, quarta-feira da 3.ª semana", "Anualmente a 15 de janeiro" |
| Repeat descriptions | "Weekly on Monday, Wednesday" or "Semanalmente (segunda-feira, quarta-feira)" |

Dates and times are handled with the [Temporal API](https://tc39.es/proposal-temporal/docs/), through `@js-temporal/polyfill`, so they do not depend on the browser's time zone. An event at `10:00` shows at 10:00 for everyone.

The first letter of the month title is always capitalised.

## Known limitations

- Only `en-US` and `pt-PT` are available, and you cannot add a language without changing the package.
